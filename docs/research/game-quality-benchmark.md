# 校园漫游：品质对标与可实施切片

研究日期：2026-10-30 UTC。范围：公开一手资料、官方静帧目视、当前代码/已有试玩截图；不修改游戏、不下载第三方包、不发布。实际包下载/骨骼检查由资产负责人独占处理。本文件是实施输入，不是游戏验收通过证明。

## 先给结论

**下一步应做一个“晴日·太理手记”完整切片，而不是继续给所有体块加窗，或再换一套 UI。** 机械馆前看钟楼 → 自由走过林荫连接段 → 清泽园取景 → 收入两枚校园印记/明信片；保持校园占地、可控第三人称和原版 Hks。用一个合适的人物、两类树形、三类地表、清晰近景阴影把这段统一起来。

优先级：**近景镜头/观景到站点 → 人物与动作 → 近景光影/地表/树群 → 取景记录玩法 → 同构建实玩与画面复验**。不增账号、后端、多人、复杂天气、巨型设置页；不承诺短期做出专业团队多年/数月的全量内容。不把“选了优秀参考”写成“本作已达市场一流”。

## 3. 自有美术方向：晴日·太理手记

这是对现有“暖晴工科校园”的收敛，不是另起一套与 DESIGN 冲突的品牌。

1. **造型：真实比例、简化细节，不是积木。** 机械馆保持源 footprint/轮廓；窗洞、檐口、台基、门廊有真实深浅；远普通楼保留简化，但不能把贴墙普通楼作为首屏/完成背景。不要给所有建筑加等量小窗。
2. **材质：大面安静，近景有触感。** 石灰暖白/旧砖、低饱和草绿、冷晴空、深松绿 UI、少量铜橙印记。铺装有细缝、路缘有高度、树下有土/草过渡；纹理对比低于建筑轮廓。现有原创细纹理先看新图，不盲换写真8K素材。
3. **植被：两种树形 + 一种低灌木已够。** 一类高干阔叶树构成树荫，一类较收拢树形作背景；树高/冠径有可控差异、成组留缺口。草簇仅在路缘/树下/花床，给门廊和钟面留视线，不均匀铺满整个校园。
4. **灯光：暖日照、冷一点的天光、可读的阴影。** 单一主日光；先把近景 shadow frustum 收紧，再考虑材质 AO。不要新增多盏投影灯、全屏 SSAO/景深/浓雾去“豪华化”。白墙不曝白、人物不黑成剪影。
5. **人物：日常校园着装，不把裸体底模直接交付。** 同一款青年比例、朴素上衣/长裤/鞋、小背包；身高1.65–1.8m设计值。真实骨骼 Idle/Walk/Run，转身平滑、脚不悬空；先一个人物做到稳定，不做角色商城。
6. **微动有节制。** 低幅树冠摆动、脚步/记录轻声即可；无声也能玩，尊重减弱动态。没有来源清楚的音效就先静音，不以资产包名称推导音乐许可。
7. **UI 是手记，不是管理后台。** 保留已有米白/深绿排版；行走时只留目标短句、两枚印记进度、地图/暂停，靠近才出现记录动作。知识与来源折叠在信息卡；完成卡不遮主观景。横屏拇指区不与拍照/返回重叠。

## 5. 最小玩法：校园印记 / 取景手记

### 一次可玩的2–4分钟切片

1. 机械馆前醒来，可立即 WASD/触控步行和转镜头；提示一句“把钟楼收入手记”，不自动走路。
2. 靠近设计观察区，画面出现细取景角标；玩家自己转动镜头把钟楼框住，按 E / 触屏“记录印记”。错误朝向只提示“再看看钟楼”，不扣分、不弹选择题阻断。
3. 自由步行穿过林荫连接段到清泽园。路只是引导，允许偏离、停留、回看；碰撞仍真实，不能通过按钮或脚本注入记录到达。
4. 在园区把“绿地前景 + 机械馆远景”的画面收入第二枚；出现小幅记录反馈和可关闭完成卡。继续漫游/重玩/进入 Hks 均可，返回校园保持位置。
5. 可选“保存明信片”在后一步加入：只导出本地游戏画面，不上传，不建账号；**没做实际截图捕获时只叫印记卡，别伪称玩家照片。**

保留 feature/landmark/save ID，不为了取景移动建筑。建议加独立、很小的 `observation` 设计配置，旧 `arrival` 和普通章节可并存，不强改所有地标数据。

## 6. 实施包与停止扩张条件

| 顺序 | 一个完整改动包 | 交回证据 |
|---|---|---|

| **P1 取景玩法** | 两站自主取景/记录/完成卡/重玩；保留普通信息和原版Hks往返，不做复杂拍摄评分系统 | 正常完成 + 看错方向 + 遮挡 + 连点 + 离开/返回 + 刷新存档 + 重玩 |
| **P2 实证收敛** | 最终同一身份静态/单元/构建/E2E、fresh review、真实桌面/横屏触摸、性能；必要时再优化 | 明确哪些是硬件实测、模拟触屏、软件渲染；未测项保留未知 |

**这轮退出标准不是文档写完，也不是模型导入成功，而是上面两枚印记的整条旅程运行且画面统一。** 未达就继续修该切片，不扩全校园精模/新玩法菜单。

## 7. 可证伪的验收标准

以下数值是本项目设计/工程门槛，不是假装来自竞品实测。

- **构图**：正常跟随人物约占可玩画面高度18–28%；近墙不持续充满屏/裁头脚，碰撞缩距时正确淡出。三节拍与完成时都有可辨目标/空间，不用整面贴墙背景交付。
- **人尺度**：角色1.65–1.8m设计高度；路缘约0.1–0.18m、椅面约0.4–0.5m仅作自制道具设计尺度。建筑 footprint/ID 检查不变，未知楼高/装饰仍注明估计。
- **美术**：三处无UI截图同时看得出主体/背景、暖冷与明暗层次；地表不空白、不过度花噪；树有树形差异但不遮钟楼。选择的真实模型不能比程序回退更不协调。
- **动画/控制**：自然按键起停、斜向/倒退/转镜头后行走、跑跳/落地、贴墙滑动、失焦清键；脚不明显滑步/穿地，动作不因低帧短按丢失。动画挂载不改变胶囊物理标尺。
- **观察玩法**：未到区、背对目标、被另一建筑挡住均不能记录；两次自然记录→完成→重玩无残留；连点不重复发奖；键盘与真实 hasTouch 双区输入均可完成。
- **UI**：1440×900级桌面与844×390级横屏触屏测试；主画面优先、提示可读、左移右转可同时操作、E/记录/返回不争输入。竖屏可提示旋转并可退出，Hks逻辑1280×720不改。
- **性能**：先在明确的硬件GPU/浏览器/网络上测冷启动与连续路线；目标≤5s可交互、p95帧时≤33.3ms（30FPS底线，桌面争取60）。记录采样长度/视口/质量档、draw calls/三角面/资源。现有 SwiftShader 约2.76FPS只证明软件渲染压力，**既不能推成普通手机帧率，也不能忽略为已达标**。
- **预算建议**：新增切片角色/环境下载净增先控在5MB压缩量内、1个人物常态≤20k三角、最多3类近景植被、单sun；这些只作预警，不是有数值就必然快。优先分块剔除/共用材质，避免全校常驻高密草或多pass后处理。
- **许可与回退**：实际文件/作者/许可/hash齐全；新资产失败仍能走路/退出；重复切校区、Hks退出、WebGL恢复不泄漏input/音频/资源。发布与远端/CI仍由主控执行，当前研究不构成发布证据。

### 有关 Three 的实现依据

- [颜色管理官方手册](https://threejs.org/manual/pages/color-management.html)：颜色贴图标 sRGB；normal/roughness 等数据贴图不标 sRGB；glTF 优先。不要重复 gamma 转换后再用滤镜纠偏。
- [阴影官方手册](https://threejs.org/manual/pages/shadows.html)：每个投影灯都增加场景渲染，选择单方向光/烘焙或便宜接触影有明确成本依据。近景阴影半径建议来自本作 texel 尺度计算，不是手册规定。
- [InstancedMesh 官方文档](https://threejs.org/docs/pages/InstancedMesh.html)：同几何/材质多变换可减少draw calls；本作仍要按空间分块并计算包围，不能把全校树合成永远可见的一块。
- [AnimationMixer 官方文档](https://threejs.org/docs/pages/AnimationMixer.html)：以delta更新；暂停/恢复/stop/uncache跟随游戏生命周期；骨骼兼容性仍需实包验证。

## 最终判断

把作品提升到可自信展示的独立游戏样板，最有杠杆的不是扩大地图或堆特效，而是：**角色像一个人、镜头像有人调过、路值得走、到达值得看、记录是玩家亲手完成的。** 当前已有校园数据/真正控制/Hks是有价值底座；这份研究没有证据可宣称“已达市场一流”，只给出了达到下一档品质所需的具体实施与验收。
