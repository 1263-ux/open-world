# 梦境邮局：恢复开发的制作取舍与验证设计

研究日期：2026-11-13。阅读了原始项目参考库、资产目录、视觉圣经 V2，目视检查 V2-02 概念板，并阅读下列官方页面。未实际试玩商业参考游戏，以下体验转译是设计建议，不冒充实机研究结论。

## 先修正生产方式

目标不是增加关卡数量，而是完成一个可以信任的垂直切片：雾海邮局收信 → 亲自改变水路 → 陪小鱼乘船 → 可选择停留/观察 → 回到邮局留下记忆。原文是“漂浮平台+断续建筑”，不是把概念板的宏大宫殿逐像素复制。AI 参考板文字不作为规格；文本 V2 优先。

先只精制三处固定视点：桥上望邮局、收信近景、舟行看云。使用同一场景布局和资产生成运行版与离线版，不建立两个独立美术世界。Blender CPU 证明构图和资产可以评审，不证明浏览器最终效果。相机、材质和灯光在不同渲染器中仍须复核。

## 从参考提炼具体交互，而非照抄外观

- A Short Hike 官方描述可沿路线或探索、遇人和找隐藏发现：https://ashorthike.com/ 。转译：第一章水路是一条清晰主线，但给一条短岸路和一个可回望的停留点。支线反馈改变小鱼动作/声音，不放一串没有意义的收集币。
- Spiritfarer 官方把照料、日常活动与关系并置：https://thunderlotusgames.com/games/spiritfarer/ 。转译：先让玩家做一个有对象的照料动作，再读感谢信。第一次撑开遮雨纸叶时，小鱼不再躲闪并靠近船边；感谢才有玩家参与的依据。这里只借关系设计原则，不移植管理/种田系统。
- TOEM 官方以摄影观察发现世界：https://www.somethingwemade.se/toem/ 。转译：看云不是到点弹窗。玩家转动视角寻找云形，小鱼朝它游；停留自愿。纪念画面来自玩家实际见过的地点，不强制做摄影收集任务。
- Dordogne 官方以童年与家庭记忆为主题：https://store.steampowered.com/app/1272840/Dordogne/ 。转译：读信回放对应真实游玩过的3个地点，不使用陌生概念图替代；童年愿望通过具体物件而非旁白说明。

## 立刻能执行的5个小实验

1. **雾的可读性**：3个固定相机×低中高雾；人物、交互物、出口应同时辨认。先不用Bloom/景深，以免掩盖错误。选中档后才加少量局部灯光。
2. **形体与材质**：只做一组精制拱门/断续窗框/灯/浅水面。同一视点A=现在资产，B=统一圆角、粗糙度、尺度后的资产；判断有没有去掉玩具拼装感。不要复杂雕花。
3. **水路动作的因果**：旋转纸片时实际水流朝向立即变；错误朝向应看见水溢出，正确则小鱼游过去。不能只有提示文字变化。无惩罚，重置不丢进度。
4. **开场情感钩子**：保留原信文本；读信前看到小鱼重复望向高处窗外的云。读完后玩家知道“为谁做、为何做”，不只知道按E。
5. **结尾对应性**：收集实际事件标记（撑纸叶/看云/停留），回放只选择发生过的片段；静默3秒保留，但不得强制93秒不可跳过。原信不是每章固定公式。

## 验证不是只跑单元测试

三层分别报告：
- 逻辑证据：故事分支、重复交互、重载恢复、暂停、快进/跳过、坏存档、速度在15/60fps一致；已有纯模块继续用Node测试。
- 静态视觉证据：3个固定相机、相同尺寸、标注离线渲染、并排参考/当前/A-B；资产来源与渲染参数可重现。不能宣布实时验收通过。
- 实机待验：相机绕墙、移动方向、镜头遮挡、按键焦点、触屏误触、音频播放、加载与帧时间；无可用浏览器时保持待验，不以它阻止前两层。

当前恢复实现已有相当完整纯状态机与控制器测试；下一步优先补 **视觉反馈是否真实发生、相机与碰撞的用户体验**，而不是继续新增测试数量装作完成。

## 轻工作流，重结果

每轮只选一个最大落差 → 做两种具体实现/参数 → 固定视点或动作录制比较 → 独立评审指出剩余缺陷 → 留下可运行版本。无需每轮新建大型规格书。每轮有实质成果就提交远端并核验tree/commit；里程碑另外保存ZIP及校验值，做一次从备份解包启动。Git本地commit不是外部备份。证据与资产一起存，不能只存README。

能力补足的优先级：场景美术统一 > 主角动画与控制体验 > 声音和叙事因果 > 扩展章节。不要因被批评“薄”就堆更多系统，也不要因电脑弱把游戏降级为图文菜单。
