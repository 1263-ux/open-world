# 双校区建设 · 批准风格落地

2026-10-31 UTC。C2 + R-ui + R-runtime + R-architecture + A3。

## G0 与最新方向
- Product core：以真实米制占地、人尺度角色，连续探索迎西与虎峪的横屏第三人称校园游戏。
- Primary user：校园访客、学生、校友；既能辨认校园，也能完成探索、摄影和 Hks 往返。
- Role ownership：Agent 调研、实施、实际试玩、自主纠错与独立复核；主控集成、验证后直推已有 main/升级已有公开站，用户判断重大体验。
- Non-goals：不新增后端、多人、账号、室内/BIM或地图引擎；不声称逐栋测绘级复刻。**双校区完整美术与可用旅程已是本轮目标，不再局限迎西单段。**
- Forbidden claims：样例批准≠书屋是真实校园；占地米制≠楼高实测；截图/单测≠真实操控；软件渲染≠真机；候选/旧CI≠新版上线；未自然到达Hks后期≠通关。

用户最新：“那你就按照这个风格建设两个校区吧”。批准对象为实际样例的视觉语言，不是Tiny Glade品质等同声明，也不是用虚构书屋替换真实校区；原暂停仅在本轮双校区范围解除。AGENTS 的首个品质切片是历史起点，不能被解释为禁止本轮建设双校区。其余安全、许可、发布与实证规则保持。

用户补充已确认：采用先前六角色的真实比例、建筑细节、材质区分、变化植被、柔和暖冷光与纸感UI方向，并按批准样例继续推进；**左上角必须有小地图，点击展开全景预览**。六角色是覆盖能力，不强制另造六个并发实现者。

## 空间与建筑层级
- yingxi（迎西）：既有155 features/16 roads。机械馆钟楼与长翼为辨识焦点，清泽园形成庭园开合，图书馆/主楼轴线与背景教学楼延续同一材质家族。保留真实轮廓，既有园景仍注明场景设计。
- huyu（虎峪）：既有95 features/2 roads。北门仍是示意锚点，梅花教室五组低层组合与主楼、图书馆、训练馆形成不同于迎西的体量节奏；优先使已有游戏路径、树荫、坐凳、入口前场连续可读，而非虚构更多“真实道路”。
- 普通楼体以足够的窗框、檐口/基座和颜色秩序收尾；地标保留轮廓/高度状态/特征。细叶/家具使用实例化与分块，保持原 GLB 懒加载、替换隐藏与释放。
- 角色约1.75m与既有米制速度不为美术改比例；不改 spatial.json 源占地、地标/存档ID、摄影目标与任务顺序。

## 验收（必须针对最终同一身份）
| 结果 | 实证 |
|---|---|
| 两校园同风格但不同身份 | 每校区至少三处正常游玩相机图：迎西机械馆/园景连接/图书馆轴线；虎峪北门主楼/梅花/图书馆运动联系。人、建筑、路面同框，无巨型球树/重复书屋/远处未收尾白盒 |
| 连续可玩 | 两校区各自主任务由真实键鼠逐站走完；转向停止、失焦、贴墙碰撞与边界；不得写位置/任务状态制造通过 |
| 手机横屏 | 844×390或类似 hasTouch 模拟，左移右转同时输入、松手停止、地图返回与关键按钮；标明非真机 |
| 左上小地图与全景 | 两校区均显示左上SVG小地图，保留真实轮廓/道路与校区名；点击复用既有全3D地图全景，清晰返回人物，打开/关闭不改位置/朝向/任务/摄影；触屏可点且不遮主要操控，不建立第二WebGL渲染器 |
| 不回退 | 双校区切换、地图往返、来源说明、刷新存档、摄影取景/记录/导出、Hks进入战斗再退出/重入保持校园位置与进度 |
| 性能与生命周期 | 同环境记录draw/triangles/帧与加载；切换重复无泄漏/错误。30FPS与5秒仅目标，无实测不写通过 |
| 发布 | 适用静态/单测/构建/E2E+独立fresh review；远端SHA、CI终态、同构建公开资源/旅程与回滚身份明确 |

Hks仍保留完整固定上游1280×720/420秒，不为本轮美术改平衡或重写。历史自然失败与未见Boss/胜利限制不消失；本轮做受影响往返回归，不无依据再做多轮长局。参考 jlu 仅已观察UI、3D玩法未知，不宣称全面超过。
