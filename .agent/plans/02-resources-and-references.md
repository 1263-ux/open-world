# Open World · 太理校园世界：资源配置与开源参考

> Draft 0.1 · 第三方资源进入仓库前，必须登记来源和许可证。

## 1. 资源清单制度

建立 `docs/resources/ASSET_SOURCES.md`。每项记录：名称、URL、作者/机构、许可证、获取日期、允许用途、署名要求、是否允许改编、文件路径、核验状态。

资源分四类：校园事实资料、空间底图、3D 资产、游戏与交互参考。

## 2. 校园地图与信息来源

### 第一优先级：学校官方资料
- 太原理工大学官网：<https://www.tyut.edu.cn/>
- 优先查找虎峪、迎西校区平面图、校园风光、官方新闻与院系地图附件。
- 建筑名称与校园事实以官方信息为准；不确定信息标记 `unverified`，不允许 Agent 猜测。

工作流程：
1. 收集两个校区的平面图、建筑照片和可确认楼宇名称。
2. 标注校门、道路交叉口、建筑轮廓、广场和绿地。
3. 选定局部原点和统一比例，先还原道路与建筑占地，再制作 3D 体块。
4. 为重点建筑记录证据链接、照片角度、确认程度和模型版本。
5. 用现场照片/团队反馈纠正错误，并记录拍摄日期。

### 第二优先级：公开地图数据
- OpenStreetMap：<https://www.openstreetmap.org/>
- OSM 版权与署名：<https://www.openstreetmap.org/copyright>
- Overpass Turbo：<https://overpass-turbo.eu/>

可评估公开地图作为道路和地物参考，但要核验数据许可及服务条款。不要默认地图瓦片可随意下载、拼接、打包或离线缓存；不要绕过访问限制批量抓取。商业地图、卫星影像和瓦片服务必须逐项检查授权。

### 第三优先级：现场照片与反馈
- 只拍摄公开区域的建筑外观、道路、门牌与标识。
- 避免采集可识别个人、门禁或安防细节。
- 用户投稿照片需要明确授权，不能默认纳入公开素材库。

## 3. 3D 资产与建模分级

候选资源（使用前核验具体许可）：
- Blender：<https://www.blender.org/>
- Poly Haven：<https://polyhaven.com/>
- Kenney：<https://kenney.nl/assets>
- Sketchfab：<https://sketchfab.com/>
- ambientCG：<https://ambientcg.com/>

分级策略：
- **L0 远景建筑：** 简单体块，保证校园轮廓。
- **L1 普通建筑：** 复用模块、窗户贴图、低面数。
- **L2 地标建筑：** 按照片还原关键轮廓与颜色。
- **L3 互动区域：** 只对需要点击、进入或动画的区域精细优化。

先把空间关系做正确，比过早雕刻窗框更重要。

## 4. 开源项目参考

### Three.js
- <https://github.com/mrdoob/three.js>
- 研究相机、光照、GLTFLoader、Raycaster 点击检测、实例化网格和性能优化。优先学习官方示例，不要整份复制示例应用。

### Hks（用户指定）
- Fork：<https://github.com/1263-ux/Hks>
- 上游：<https://github.com/ShanEior/Hks>
- 仓库结构显示它是 TypeScript/Vite 项目，包含 `src/`、`public/assets/`，以及 Agent/Skill 说明文件。
- **当前仓库元数据未显示明确许可证，不能因此假设代码、图像、音效或素材可以直接复制、改编或再分发。** 必须检查 LICENSE 或取得原作者许可，并分别核验第三方素材授权。

推荐集成步骤：
1. 本地运行，记录启动命令、依赖、玩法与素材清单。
2. 核验仓库许可证、上游许可和素材来源。
3. 先做独立路由或 iframe 原型，测试加载、交互和性能。
4. 若要深度整合，再抽取玩法逻辑；不要无差别复制整套素材。
5. 小游戏必须有返回校园入口；加载失败不能卡住主场景。

### 其他小游戏/框架候选
- Phaser：<https://github.com/phaserjs/phaser>，成熟 2D 游戏框架，适合独立小游戏，不作为主 3D 引擎。
- Kaboom.js：<https://github.com/replit/kaboom>，可研究轻量 2D 游戏开发方式；使用前核验维护状态和许可。
- 2048：<https://github.com/gabrielecirulli/2048>，可参考极简益智玩法，集成前核验许可证和署名要求。
- js13kGames：<https://js13kgames.com/>，发现小体量 Web 游戏；每个作品都要单独核验许可。
- Three.js 示例：<https://threejs.org/examples/>

## 5. MCP 与自动化工具

MCP 应解决明确问题，不是越多越先进。
- **GitHub MCP/连接器：** 读取仓库、检查依赖与许可证、整理 Issue/PR；写入操作需项目负责人确认。
- **Playwright：** 验证校区切换、地标点击、小游戏进入/退出和移动端布局。
- **网页资料检索 MCP：** 只有在能提供来源 URL、发布时间和可核对证据时才使用；结果需人工核对。
- **Blender 自动化：** 脚本检查模型命名、导出 GLB 和统计体积；未经预览不得批量覆盖源模型。
- **首版不建议接入：** 重复搜索 MCP、付费地图 API、向量数据库、运行时多 Agent 框架。

## 6. 资源许可门禁

每项资源合入前回答：
- 许可证是什么，是否允许修改和再分发？
- 是否需要署名、保留声明或公开衍生作品？
- 代码与素材的许可证是否不同？
- 是否允许商业用途？项目未来可能公开或变现，不能忽略这一点。
- 是否已把许可证、原始 URL 和作者写入来源清单？

不能确认的资源标记 `blocked`，用自制占位资源替代，不得悄悄合入。
